Aula 24 — Algoritmos – Parte 3

O que você vai aprender nesta aula

Ao final desta aula, você será capaz de:

  • explicar por que algoritmos precisam repetir determinadas ações;
  • identificar uma estrutura de repetição em um problema;
  • usar ENQUANTO para repetir enquanto uma condição for verdadeira;
  • usar PARA quando a quantidade de repetições for conhecida;
  • utilizar contadores e acumuladores em algoritmos;
  • compreender a estrutura REPITA...ATÉ;
  • executar um teste de mesa acompanhando várias repetições.

1. Quando precisamos repetir?

Na Aula 22, vimos algoritmos sequenciais. Na Aula 23, aprendemos que um algoritmo pode escolher caminhos diferentes usando decisões.

Mas imagine um sistema que precisa mostrar os números de 1 até 100. Seria necessário escrever: 

escreva(1)
escreva(2)
escreva(3)
escreva(4)
...
escreva(100)

Isso funcionaria, mas seria uma solução enorme, repetitiva e difícil de alterar.

E se fossem 1.000 números? E se o número mudasse?

É justamente para isso que existem as estruturas de repetição.

Ideia central: quando uma mesma ação precisa ser executada várias vezes, podemos ensinar o algoritmo a repetir essa ação automaticamente.

Repetições estão em toda parte

  • verificar cada produto de uma lista;
  • mostrar todos os alunos de uma turma;
  • somar vários valores;
  • tentar uma senha enquanto ela estiver incorreta;
  • processar todos os pedidos de uma fila;
  • contar quantas pessoas responderam a uma pesquisa;
  • reproduzir músicas uma após outra.

2. O que é uma estrutura de repetição

Uma estrutura de repetição, também chamada de laço ou loop, permite executar um conjunto de instruções várias vezes.

Diferentemente de simplesmente copiar e colar as mesmas instruções, o algoritmo controla quando deve continuar repetindo e quando deve parar.

Todo loop precisa responder a uma pergunta:

"Quando devo continuar e quando devo parar?"

Existem diferentes maneiras de responder a essa pergunta.

Estrutura Quando usar
ENQUANTO Quando a repetição depende de uma condição.
PARA Quando sabemos a quantidade ou o intervalo de repetições.
REPITA...ATÉ Quando queremos executar pelo menos uma vez e repetir até uma condição acontecer.

3. ENQUANTO: repetir enquanto uma condição for verdadeira

A estrutura ENQUANTO verifica uma condição antes de cada repetição.

Estrutura básica: 

enquanto condição faça
    instruções
fimenquanto

Exemplo: 

contador ← 1

enquanto contador <= 5 faça
    escreva(contador)
    contador ← contador + 1
fimenquanto

O algoritmo mostra: 

1
2
3
4
5

Quando contador passa a valer 6, a condição contador <= 5 se torna falsa. O loop termina.

O passo mais importante: atualizar a variável

Observe: 

contador ← contador + 1

Essa instrução é fundamental. Ela faz o contador avançar.

Se esquecermos essa atualização: 

contador ← 1

enquanto contador <= 5 faça
    escreva(contador)
fimenquanto

contador continuará valendo 1 para sempre. A condição continuará verdadeira e o algoritmo poderá ficar preso em um loop infinito.

Regra prática: se uma variável participa da condição de um ENQUANTO, verifique como ela será alterada dentro do loop.

ENQUANTO no dia a dia

Pense em uma pessoa tentando fazer login: 

enquanto senha estiver incorreta
    pedir senha novamente

O número de tentativas pode não ser conhecido antecipadamente. A repetição depende de uma condição.

4. PARA: repetir uma quantidade conhecida de vezes

Quando sabemos exatamente quantas vezes queremos repetir uma ação, a estrutura PARA costuma ser mais adequada.

Exemplo: 

para i de 1 até 5 faça
    escreva(i)
fimpara

Resultado: 

1
2
3
4
5

A variável i funciona como um contador automático.

Comparando PARA e ENQUANTO

PARA ENQUANTO
Sabemos o intervalo ou quantidade. A quantidade pode depender da situação.
O contador é controlado pela estrutura. Precisamos controlar a variável.
Ex.: repetir 10 vezes. Ex.: repetir enquanto houver itens.

Exemplo: mostrar uma lista numerada

para i de 1 até 10 faça
    escreva("Item ", i)
fimpara

Saída: 

Item 1
Item 2
Item 3
Item 4
Item 5
Item 6
Item 7
Item 8
Item 9
Item 10

PARA também pode contar de outros valores

para i de 5 até 10 faça
    escreva(i)
fimpara

Resultado: 

5
6
7
8
9
10

O importante é entender que a variável de controle percorre um intervalo determinado.

5. Contadores e acumuladores

Loops ficam ainda mais poderosos quando usamos variáveis para contar ou acumular informações.

5.1 Contador

Um contador guarda a quantidade de vezes que algo aconteceu. 

contador ← 0

para i de 1 até 5 faça
    contador ← contador + 1
fimpara

escreva(contador)

Resultado: 

5

O contador começa em zero e aumenta uma unidade a cada ocorrência.

5.2 Acumulador

Um acumulador guarda uma soma progressiva.

Por exemplo, somar os números de 1 até 5: 

soma ← 0

para i de 1 até 5 faça
    soma ← soma + i
fimpara

escreva(soma)

O resultado será: 

15

Porque: 

0 + 1 = 1
1 + 2 = 3
3 + 3 = 6
6 + 4 = 10
10 + 5 = 15

Contador × acumulador

Contador Acumulador
Objetivo Contar ocorrências. Acumular valores.
Exemplo Quantidade de alunos. Soma das notas.
Atualização típica contador ← contador + 1 soma ← soma + valor

Exemplo completo: média de cinco notas

soma ← 0

para i de 1 até 5 faça

    escreva("Digite a nota: ")
    leia(nota)

    soma ← soma + nota

fimpara

media ← soma / 5

escreva("Média: ", media)

Aqui temos:

  • i → controla as cinco repetições;
  • nota → guarda a nota atual;
  • soma → acumulador;
  • media → resultado final.

6. REPITA...ATÉ: repetir até uma condição acontecer

Existe uma situação diferente: queremos executar o bloco pelo menos uma vez e só depois verificar se devemos continuar.

Para isso podemos usar REPITA...ATÉ. 

repita
    instruções
até condição

Exemplo: 

repita

    escreva("Digite uma senha:")
    leia(senha)

até senha = "1234"

A pessoa precisa digitar pelo menos uma senha. Depois disso, o algoritmo verifica se ela está correta.

Se estiver errada, o bloco será repetido. Quando a condição se tornar verdadeira, o loop termina.

ENQUANTO × REPITA...ATÉ

ENQUANTO REPITA...ATÉ
Testa antes de executar. Executa antes de testar.
Pode executar zero vezes. Executa pelo menos uma vez.
Continua enquanto a condição for verdadeira. Continua até a condição ser verdadeira.

Essa diferença parece pequena, mas pode mudar completamente o comportamento de um algoritmo.

7. Escolhendo a estrutura adequada

Uma das habilidades importantes em programação não é apenas saber escrever um loop, mas saber qual loop utilizar.

Situação Estrutura indicada Por quê?
Mostrar números de 1 a 10 PARA O intervalo é conhecido.
Ler alunos enquanto houver alunos ENQUANTO A repetição depende de uma condição.
Pedir uma senha até acertar REPITA...ATÉ A tentativa precisa acontecer pelo menos uma vez.
Somar 20 valores PARA A quantidade de valores é conhecida.
Processar pedidos enquanto existirem pedidos ENQUANTO O fim depende da situação.

Uma pergunta que ajuda muito

Eu sei antecipadamente quantas vezes preciso repetir?

Se a resposta for sim, PARA costuma ser uma boa escolha.

Se a resposta for não, pense em ENQUANTO ou REPITA...ATÉ, dependendo de quando a condição deve ser verificada.

8. Teste de mesa com repetições

Na Aula 23 aprendemos a acompanhar os caminhos de decisão. Agora precisamos acompanhar também cada repetição.

Considere: 

soma ← 0

para i de 1 até 4 faça
    soma ← soma + i
fimpara

escreva(soma)

Podemos construir uma tabela:

Repetição i soma antes Operação soma depois
1 1 0 0 + 1 1
2 2 1 1 + 2 3
3 3 3 3 + 3 6
4 4 6 6 + 4 10

Portanto: 

soma = 10

Teste de mesa com ENQUANTO

contador ← 1

enquanto contador <= 3 faça

    escreva(contador)

    contador ← contador + 1

fimenquanto
Momento contador contador <= 3? Ação
Antes da 1ª 1 Verdadeiro Mostra 1
Antes da 2ª 2 Verdadeiro Mostra 2
Antes da 3ª 3 Verdadeiro Mostra 3
Depois 4 Falso Encerra

9. Erros comuns nos loops

Erro Exemplo Como corrigir
Loop infinito contador nunca é alterado. Atualize a variável usada na condição.
Começar contador no valor errado Começar em 0 quando a sequência deveria começar em 1. Defina claramente o início.
Terminar antes ou depois Repetir até 9 quando deveria chegar a 10. Teste os limites.
Acumulador sem inicialização soma ← soma + valor sem definir soma. Inicialize soma, geralmente com 0.
Confundir contador e acumulador Somar valores usando apenas +1. Contador conta ocorrências; acumulador acumula valores.
Escolher estrutura inadequada Usar PARA para uma repetição sem quantidade conhecida. Analise como o loop deve terminar.
Não testar zero ocorrências O ENQUANTO começa com condição falsa. Verifique se o algoritmo funciona mesmo sem entrar no loop.

O perigo do loop infinito

Observe: 

contador ← 1

enquanto contador <= 5 faça

    escreva(contador)

fimenquanto

O problema está no fato de que contador nunca muda.

A condição continuará sendo: 

1 <= 5

indefinidamente.

Antes de executar um loop, pergunte: "Qual variável ou acontecimento fará a condição mudar?"

10. Resumo da aula

  • Estruturas de repetição permitem executar várias vezes um mesmo conjunto de instruções.
  • Todo loop precisa ter uma forma clara de determinar quando continuar e quando parar.
  • ENQUANTO testa a condição antes de cada repetição.
  • PARA é adequado quando o intervalo ou número de repetições é conhecido.
  • REPITA...ATÉ executa primeiro e testa depois, garantindo pelo menos uma execução.
  • Contadores registram quantas vezes algo aconteceu.
  • Acumuladores guardam uma soma ou outro valor que vai sendo atualizado.
  • Um loop infinito acontece quando a condição de parada nunca se torna falsa.
  • O teste de mesa ajuda a acompanhar cada repetição e descobrir erros.

Glossário

  • Repetição: execução de um conjunto de instruções várias vezes.
  • Loop: estrutura utilizada para controlar uma repetição.
  • ENQUANTO: repete enquanto uma condição for verdadeira.
  • PARA: repete seguindo um intervalo ou quantidade definida.
  • REPITA...ATÉ: executa o bloco e repete até que uma condição seja verdadeira.
  • Contador: variável utilizada para contar ocorrências.
  • Acumulador: variável que guarda progressivamente um valor, geralmente uma soma.
  • Loop infinito: repetição que não consegue chegar à condição de parada.
