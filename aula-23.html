Aula 23 — Algoritmos – Parte 2

O que você vai aprender nesta aula

Ao final desta aula, você será capaz de:

  • explicar por que alguns problemas precisam de decisões;
  • usar operadores relacionais para comparar valores;
  • escrever algoritmos usando as estruturas SE e SE...SENÃO;
  • combinar condições usando operadores lógicos;
  • representar decisões em pseudocódigo e fluxogramas;
  • executar um teste de mesa envolvendo diferentes caminhos de um algoritmo.

1. Quando a sequência não é suficiente

Na Aula 22, trabalhamos com algoritmos sequenciais: as instruções eram executadas uma depois da outra, sempre na mesma ordem.

Mas muitos problemas do mundo real não funcionam assim. Às vezes, o próximo passo depende de uma condição.

Imagine um sistema escolar que precisa verificar se um aluno foi aprovado. Ele não pode simplesmente mostrar "Aprovado" para todos. Primeiro precisa analisar a média. 

Se média >= 6
    mostrar "Aprovado"
Senão
    mostrar "Em recuperação"

O algoritmo precisa tomar uma decisão.

Ideia central: uma estrutura de decisão permite que um algoritmo escolha caminhos diferentes de acordo com uma condição.

Exemplos de decisões presentes em sistemas:

  • Se a senha estiver correta, permitir acesso.
  • Se houver estoque, liberar a compra.
  • Se a idade for maior ou igual a 18, permitir determinada operação.
  • Se a temperatura estiver acima do limite, ligar o ventilador.
  • Se o pagamento for aprovado, confirmar o pedido.

2. O que é uma decisão em um algoritmo

Uma decisão acontece quando o algoritmo precisa verificar uma condição antes de escolher o próximo passo.

Uma condição é uma pergunta que pode ter uma resposta lógica: verdadeiro ou falso.

Condição Resposta possível
idade >= 18 Verdadeiro ou falso
nota >= 6 Verdadeiro ou falso
senha = "1234" Verdadeiro ou falso
estoque > 0 Verdadeiro ou falso

É importante perceber que a condição não é uma ação. Ela é uma pergunta que ajuda o algoritmo a decidir qual ação executar.

Por exemplo: 

idade >= 18

significa: "A idade é maior ou igual a 18?"

Já: 

mostrar "Entrada permitida"

é uma ação.

O modelo mental

Início
↓
Ler idade entrada
↓
idade >= 18? decisão
↙      ↘
Sim permitir entrada
Não negar entrada

Uma decisão divide o caminho do algoritmo de acordo com uma condição.

3. Operadores relacionais

Para criar condições, precisamos comparar valores. Os símbolos utilizados para fazer essas comparações são chamados de operadores relacionais.

Operador Significado Exemplo
> maior que idade > 18
< menor que nota < 6
>= maior ou igual a idade >= 18
<= menor ou igual a nota <= 10
= igual a senha = "1234"
<> diferente de status <> "pago"

Exemplos

7 > 5       → verdadeiro
7 < 5       → falso
7 >= 7      → verdadeiro
7 = 8       → falso
10 <> 3     → verdadeiro

O resultado de uma comparação é sempre um valor lógico: verdadeiro ou falso.

Um cuidado importante

Compare com atenção o significado de cada operador.

Se a regra for:

"Aluno com média 6 ou mais está aprovado."

a condição correta é: 

media >= 6

Usar apenas media > 6 faria com que uma média exatamente igual a 6 fosse considerada reprovada.

4. Estrutura SE

A estrutura SE permite executar uma ação somente quando uma condição for verdadeira.

Estrutura básica:

se condição então
    instrução
fimse

Exemplo: 

se idade >= 18 então
    escreva("Maior de idade")
fimse

Se a idade for 20, a mensagem será mostrada. Se a idade for 16, nada acontecerá dentro desse bloco.

Exemplo completo

algoritmo "VerificaIdade"

var
   idade: inteiro

inicio

   escreva("Digite sua idade: ")
   leia(idade)

   se idade >= 18 então
      escreva("Acesso permitido")
   fimse

fimalgoritmo

Observe que a decisão não substitui a sequência. O algoritmo continua sendo executado de cima para baixo, mas agora existe um possível caminho que pode ou não ser executado.

5. Estrutura SE...SENÃO

E se precisarmos executar uma ação quando a condição for verdadeira e outra ação quando for falsa?

Nesse caso usamos SE...SENÃO. 

se condição então
    instrução 1
senão
    instrução 2
fimse

Exemplo: aprovação

algoritmo "SituacaoAluno"

var
   media: real

inicio

   escreva("Digite a média: ")
   leia(media)

   se media >= 6 então
      escreva("Aprovado")
   senão
      escreva("Não aprovado")
   fimse

fimalgoritmo

Existem dois caminhos possíveis:

Condição Caminho Resultado
media >= 6 é verdadeira SE Aprovado
media >= 6 é falsa SENÃO Não aprovado

Fluxograma

Início
↓
Ler média entrada
↓
média >= 6? decisão
↙      ↘
Sim Mostrar "Aprovado"
Não Mostrar "Não aprovado"
↘      ↙
Fim

As duas possibilidades voltam para o fluxo principal e chegam ao fim.

6. Decisões com várias possibilidades

Alguns problemas possuem mais de duas possibilidades.

Imagine um sistema que classifica uma nota:

  • nota menor que 5 → insuficiente;
  • nota entre 5 e 6,9 → recuperação;
  • nota igual ou maior que 7 → aprovado.

Podemos representar essa situação com decisões encadeadas. 

se nota < 5 então
    escreva("Insuficiente")
senão
    se nota < 7 então
        escreva("Recuperação")
    senão
        escreva("Aprovado")
    fimse
fimse

O segundo se só é analisado quando a primeira condição foi falsa.

Outro exemplo: faixa etária

se idade < 12 então
    escreva("Criança")
senão
    se idade < 18 então
        escreva("Adolescente")
    senão
        escreva("Adulto")
    fimse
fimse

A ordem das condições importa. O algoritmo testa uma condição e só passa para a próxima quando necessário.

Dica: quando houver muitas possibilidades, escreva primeiro as regras em linguagem comum. Depois transforme cada regra em uma condição.

7. Operadores lógicos

Às vezes uma decisão depende de mais de uma condição. Nesse caso usamos operadores lógicos.

Operador Ideia Exemplo
e As duas condições precisam ser verdadeiras. idade >= 18 e possuiDocumento = verdadeiro
ou Pelo menos uma condição precisa ser verdadeira. pix = verdadeiro ou dinheiro = verdadeiro
não Inverte o valor lógico. não bloqueado

Operador E

Considere: 

idade >= 18 e documento = verdadeiro

Para a expressão inteira ser verdadeira, as duas condições precisam ser verdadeiras.

Idade >= 18 Documento Resultado
Verdadeiro Verdadeiro Verdadeiro
Verdadeiro Falso Falso
Falso Verdadeiro Falso
Falso Falso Falso

Operador OU

Agora considere: 

pix = verdadeiro ou dinheiro = verdadeiro

Basta uma das opções ser verdadeira para a expressão inteira ser verdadeira.

Pix Dinheiro Resultado
Verdadeiro Verdadeiro Verdadeiro
Verdadeiro Falso Verdadeiro
Falso Verdadeiro Verdadeiro
Falso Falso Falso

Exemplo prático

Um sistema permite uma atividade somente para estudantes com idade entre 15 e 18 anos. 

se idade >= 15 e idade <= 18 então
    escreva("Pode participar")
senão
    escreva("Não pode participar")
fimse

Aqui as duas condições precisam ser verdadeiras: a idade deve ser pelo menos 15 e no máximo 18.

8. Teste de mesa com decisões

Na Aula 22 vimos que o teste de mesa permite acompanhar os valores das variáveis durante a execução.

Com decisões, precisamos acompanhar também qual caminho foi escolhido.

Considere o algoritmo:

algoritmo "Desconto"

var
   idade: inteiro
   preco: real

inicio

   idade ← 16
   preco ← 100

   se idade < 18 então
      preco ← preco * 0.90
   fimse

   escreva(preco)

fimalgoritmo

Como a idade é 16, a condição idade < 18 é verdadeira. Portanto, o desconto será aplicado.

Passo Instrução idade preco Condição
1 idade ← 16 16
2 preco ← 100 16 100
3 idade < 18? 16 100 Verdadeiro
4 preco ← preco * 0.90 16 90
5 escreva(preco) 16 90

O resultado mostrado será: 

90

E se a idade fosse 20?

Nesse caso: 

idade < 18

seria falso. O bloco do se não seria executado e o preço continuaria sendo 100.

Teste de mesa com decisão: acompanhe os valores das variáveis, avalie cada condição e marque qual caminho foi executado.

9. Erros comuns ao criar decisões

Erro Exemplo Como corrigir
Usar o operador errado media > 6 quando a regra é "6 ou mais" Use media >= 6
Esquecer um caminho Verificar apenas quem foi aprovado Use SENÃO quando o outro caso também precisar de tratamento
Confundir condição com ação se "mostrar aprovado" A condição deve ser uma pergunta lógica
Usar muitas condições sem organizar Vários SE encadeados sem explicar as regras Escreva primeiro as possibilidades em linguagem comum
Inverter a lógica Permitir acesso quando senha estiver incorreta Teste também casos verdadeiros e falsos
Não testar os limites Testar 5 e 7, mas nunca 6 Teste valores exatamente nos limites
Não testar situações diferentes Testar apenas um aluno aprovado Teste aprovação, reprovação e valores de fronteira

Um princípio importante

Se um algoritmo contém uma condição:

Teste pelo menos um caso em que ela seja verdadeira e um caso em que ela seja falsa.

E, quando existirem limites, teste também os valores exatamente sobre esses limites.

Por exemplo, para: 

se nota >= 6 então

não basta testar:

  • nota = 8;
  • nota = 4.

Também é importante testar:

  • nota = 6 → valor exatamente no limite;
  • nota = 5,9 → imediatamente abaixo do limite.

10. Resumo da aula

  • A estrutura de decisão permite que um algoritmo escolha caminhos diferentes.
  • Uma condição é uma expressão que resulta em verdadeiro ou falso.
  • Os operadores relacionais permitem comparar valores: >, <, >=, <=, = e <>.
  • A estrutura SE executa uma ação quando a condição é verdadeira.
  • A estrutura SE...SENÃO permite definir dois caminhos: um para verdadeiro e outro para falso.
  • Decisões podem ser encadeadas quando existem várias possibilidades.
  • Os operadores E, OU e NÃO permitem combinar condições.
  • O teste de mesa deve verificar tanto os valores das variáveis quanto o caminho escolhido pelo algoritmo.

Glossário

  • Condição: expressão que pode ser verdadeira ou falsa.
  • Decisão: escolha de um caminho do algoritmo com base em uma condição.
  • Operador relacional: símbolo utilizado para comparar valores.
  • SE: estrutura que executa instruções quando uma condição é verdadeira.
  • SENÃO: caminho executado quando a condição do SE é falsa.
  • Operador lógico: permite combinar ou inverter condições.
  • Caminho: sequência de instruções executada em uma determinada situação.
  • Valor de fronteira: valor exatamente no limite de uma condição e que deve ser testado.
