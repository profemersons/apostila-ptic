Aula 26 — Revisão de Pensamento Computacional

O que você vai revisar nesta aula

Nesta aula vamos reunir os conceitos estudados em Pensamento Computacional e observar como eles podem ser utilizados juntos para compreender e resolver problemas.

Ao final da revisão, você será capaz de:

  • reconhecer os quatro pilares do pensamento computacional;
  • identificar decomposição em problemas do cotidiano;
  • reconhecer padrões e repetições;
  • explicar como a abstração seleciona as informações relevantes;
  • identificar algoritmos como sequências organizadas de passos;
  • combinar os quatro pilares para analisar um problema.

1. Os quatro pilares do pensamento computacional

O pensamento computacional pode ser entendido como uma forma estruturada de analisar problemas e construir soluções. Quatro ideias aparecem com frequência nesse processo:

PilarPergunta que ele ajuda a responder
DecomposiçãoComo posso dividir este problema em partes menores?
Reconhecimento de padrõesO que se repete ou se parece com algo que já conheço?
AbstraçãoO que realmente importa para este objetivo?
AlgoritmosQuais passos organizados podem levar à solução?

Esses pilares não são quatro etapas obrigatórias que precisam sempre aparecer na mesma ordem. Eles são ferramentas de pensamento que podem se complementar.

2. Decomposição

Decompor significa dividir um problema grande ou complexo em partes menores. Isso facilita a compreensão porque podemos analisar uma parte de cada vez.

Imagine que uma escola queira criar um sistema para controlar os empréstimos da biblioteca. Em vez de tratar tudo como um único problema, podemos separar:

  • cadastro dos livros;
  • cadastro dos estudantes;
  • registro de empréstimos;
  • registro de devoluções;
  • controle de atrasos;
  • consulta da situação dos livros.

O problema continua sendo um só, mas agora está dividido em componentes que podem ser analisados individualmente.

Regra prática: se um problema parece grande demais para resolver de uma vez, procure partes menores que possam ser compreendidas separadamente.

3. Reconhecimento de padrões

Depois de dividir um problema, podemos observar as partes e procurar semelhanças, repetições e comportamentos que aparecem novamente.

Imagine que uma secretaria observe o número de atendimentos durante vários dias. Se o movimento aumenta sempre próximo do mesmo horário, existe um padrão que pode ajudar no planejamento da equipe.

Na programação, reconhecer padrões também é importante. Se várias situações seguem uma estrutura parecida, podemos pensar em uma solução que atenda a todas elas.

Exemplo

Considere estas situações:

  • calcular a média de um aluno;
  • calcular a média de outro aluno;
  • calcular a média de uma terceira pessoa.

As pessoas e as notas são diferentes, mas o processo é semelhante: receber notas → somar → dividir pela quantidade → apresentar o resultado.

Esse padrão pode ser transformado em uma solução que funcione para diferentes pessoas.

4. Abstração

Abstrair é decidir o que é essencial para o objetivo e deixar de lado detalhes que não são necessários naquele contexto.

Imagine que queremos calcular o tempo de uma viagem. Podemos precisar de:

  • distância;
  • velocidade;
  • tempo.

A cor do carro, a música tocando no rádio ou a roupa do motorista não são necessárias para esse cálculo.

O que é essencial depende do objetivo. Uma informação pode ser importante em um problema e irrelevante em outro.

A abstração ajuda a construir modelos menores e mais fáceis de compreender. Mapas, tabelas, formulários, gráficos e interfaces de aplicativos são exemplos de representações abstratas da realidade.

5. Algoritmos

Um algoritmo é uma sequência organizada de instruções para realizar uma tarefa ou resolver um problema.

Quando usamos os pilares anteriores, conseguimos chegar a uma solução mais organizada. Por exemplo, para calcular a média de duas notas:

  1. receber a primeira nota;
  2. receber a segunda nota;
  3. somar as duas notas;
  4. dividir o resultado por 2;
  5. mostrar a média.

Em pseudocódigo: 

algoritmo "media"
var
   n1, n2, media: real
inicio
   leia(n1)
   leia(n2)
   media <- (n1 + n2) / 2
   escreva(media)
fimalgoritmo

O algoritmo transforma uma ideia de solução em passos que podem ser seguidos, testados e, posteriormente, implementados em uma linguagem de programação.

6. Os pilares trabalhando juntos

Agora podemos juntar os quatro conceitos em uma situação.

Problema: organizar a entrega de trabalhos

Uma escola precisa acompanhar quais estudantes entregaram cada atividade.

1. Decomposição:

  • estudantes;
  • disciplinas;
  • atividades;
  • prazos;
  • entregas;
  • pendências.

2. Reconhecimento de padrões:

Todas as disciplinas possuem atividades, estudantes e prazos. A estrutura se repete, mesmo quando os conteúdos são diferentes.

3. Abstração:

Para controlar a entrega, precisamos de dados como estudante, disciplina, atividade, prazo e situação da entrega. Informações como cor favorita ou música preferida não são necessárias para esse objetivo.

4. Algoritmo:

  1. identificar o estudante;
  2. selecionar a disciplina;
  3. selecionar a atividade;
  4. verificar o prazo;
  5. registrar a entrega;
  6. atualizar a situação.

Observe que não começamos escrevendo código. Primeiro entendemos o problema.

7. Um problema completo para analisar

Imagine agora um aplicativo de cantina escolar que permita ao estudante reservar um lanche antes do intervalo.

Decomposição

Podemos dividir o problema em cadastro, cardápio, pedidos, pagamento, preparação e retirada.

Reconhecimento de padrões

Percebemos que vários pedidos possuem uma estrutura semelhante: estudante, item escolhido, quantidade, horário e situação.

Abstração

Para controlar o pedido, algumas informações são essenciais. A cor do cabelo do estudante, por exemplo, não é necessária para preparar o lanche.

Algoritmo

  1. identificar o estudante;
  2. mostrar os itens disponíveis;
  3. receber a escolha;
  4. verificar disponibilidade;
  5. registrar o pedido;
  6. informar o horário de retirada.

Os quatro pilares ajudaram a transformar uma situação do cotidiano em uma solução que pode ser organizada e posteriormente implementada em um sistema.

8. Do problema ao algoritmo

Podemos representar o caminho de forma simplificada:

Situação realO problema existe no mundo
↓
DecomposiçãoDividir em partes menores
↓
PadrõesEncontrar repetições e semelhanças
↓
AbstraçãoSelecionar o que é relevante
↓
AlgoritmoOrganizar os passos da solução

Os pilares podem se combinar para transformar uma situação real em uma solução organizada.

Depois disso, a solução pode ser implementada em um programa. A programação, portanto, é uma forma de colocar a solução em prática.

9. Erros comuns

Tentar resolver tudo de uma vez

Problemas grandes ficam mais fáceis quando são divididos em partes menores.

Ignorar padrões

Se situações semelhantes aparecem repetidamente, podemos procurar uma estratégia que funcione para todas elas.

Guardar informação demais

A abstração ajuda a evitar modelos cheios de dados que não serão utilizados.

Guardar informação de menos

O contrário também é um problema. Se retirarmos uma informação essencial, a solução pode deixar de funcionar.

Começar pelo código

Antes de programar, precisamos compreender o problema e organizar uma solução.

10. Resumo da aula

  • Decomposição divide um problema grande em partes menores.
  • Reconhecimento de padrões procura repetições e semelhanças.
  • Abstração seleciona o que é essencial para determinado objetivo.
  • Algoritmos organizam uma solução em passos.
  • Os quatro pilares podem trabalhar juntos.
  • O pensamento computacional pode ser utilizado antes mesmo de escrever código.
  • Uma boa solução começa pela compreensão do problema.

Ideia-chave: pensar computacionalmente é aprender a olhar para um problema, organizá-lo e construir uma solução que possa ser compreendida, testada e executada.

Glossário

  • Decomposição: divisão de um problema em partes menores.
  • Padrão: repetição ou semelhança identificável.
  • Abstração: seleção do que é relevante para determinado objetivo.
  • Algoritmo: sequência organizada de instruções.
  • Pensamento computacional: abordagem estruturada para analisar problemas e construir soluções.
